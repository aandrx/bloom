# B-4c release paperwork: licensing, engine range and the Cargo boundary

Status: review complete; Bloom MIT, upstream Apache-2.0/NOTICE and a generated
third-party notice bundle are added and staged. **Distribution is still not
ready.** No distribution claim is made, no engine library is bundled, and no live
install was rerun. Remaining blockers are legal review of the fallback/compound
notices, the external-engine review and the exact-tag-only compatibility range.
The source-side inventory and open owner decisions are in
[source-publication licenses](source-publication-licenses.md).

## Question

What must accompany a staged Bloom prefix for it to be distributable, which
OpenBubbles engine versions are supported, and what does Cargo alone fail to
provide?

## Observed facts

### Bloom's own license

- The workspace declares MIT in `Cargo.toml:16`.
- `bloom-core` and `bloom-tui` were missing the workspace license field; that
  metadata is fixed and `cargo metadata --no-deps` now reports MIT for all seven
  workspace packages.
- A root `LICENSE` now carries the MIT text with the copyright holder recorded as
  "Bloom contributors". The holder should be confirmed before distribution; the
  file is otherwise complete.

### Vendored upstream bindings

- `ext/bloom-engine-sidecar/ATTRIBUTION` records generated Dart bindings from
  OpenBubbles v1.15.0+205, commit `852c9910f456492f7f840ac4ff2a8bad7a1ee8c8`,
  under Apache-2.0.
- `lib/upstream/LICENSE` now carries the Apache-2.0 text and `lib/upstream/NOTICE`
  records the OpenBubbles attribution. Both are staged with the bindings. The
  upstream root tree at the pinned commit has no `NOTICE`, so the current file is
  Bloom's attribution rather than a reproduced upstream notice. A later byte
  comparison found one exact upstream binding and four with reproducible
  formatting differences. The reviewed refresh helper then added per-file
  modification notices; all original bodies and attribution files remained
  byte-identical. Details are in
  [source-publication licenses](source-publication-licenses.md).
- The staging dry run copies the root `LICENSE`, `lib/upstream`, `pubspec.*` and
  `ATTRIBUTION` into the prefix and does not copy an engine library.

### Third-party notice bundle

- `third-party-notices/` is generated by `scripts/generate-third-party-notices`
  from `cargo metadata` and the resolved Dart package configuration.
- The bundle covers 485 Rust and 52 Dart packages. It contains 299 unique Rust
  notice files, 25 unique Dart notice files, and generic MIT/Apache-2.0/MPL-2.0
  fallbacks for 48 Rust packages that ship no package-specific license file.
- `rust-manifest.md` and `dart-manifest.md` list package, version, license,
  repository and every included notice reference. Files are deduplicated by
  content hash. `NO FILE` is a generator state for packages with no license file;
  all 52 current Dart entries have notices, so it is not a current finding.
- `fallbacks/README.md` lists the 48 packages that use a fallback. The fallbacks
  are not substitutes for package-specific copyright notices and remain part of
  the legal review.
- `scripts/test-third-party-notices.py` validates the committed bundle and its
  references; the CI source-guard job runs it.

### Staged contents

`python3 scripts/stage-prefix --bin-dir target/debug --prefix <tmp> --with-sidecar --dry-run` plans:

- `LICENSE` (root MIT);
- `bin/bloom`, `bin/bloom-tui`, `bin/bloomd`;
- `share/bloom/third-party-notices`, the generated Rust and Dart notice bundle;
- `share/bloom/engine/bin/bloom_engine.dart`, the owned Dart libraries, the
  generated upstream bindings with their `LICENSE` and `NOTICE`, `pubspec.yaml`,
  `pubspec.lock` and `ATTRIBUTION`;
- `stage-manifest.json` with copied paths, SHA-256 digests and the upstream tag or
  commit.

It plans no engine library. `scripts/test-staging.py` passes 15 synthetic tests,
including refusal to stage a shared library, refusal without a root LICENSE, and
refusal to stage an engine library inside the prefix.

### The external engine

- The sidecar README states that the engine library is loaded at runtime only and
  is never included, copied, downloaded or bundled.
- The same README states that the engine contains SSPL and closed-source
  components. Bloom does not link against it; it stays behind the child process
  boundary.
- The installed Flatpak reports version `1.15.0.0`; the sidecar bindings were
  generated from source tag `v1.15.0+205`. The relationship between the Flatpak
  version string and the upstream source tag is not independently verified here.

### Supported engine range

- Bindings are pinned to the OpenBubbles tag above.
- `ext/bloom-engine-sidecar/dart/lib/upstream/frb_generated.dart:69` carries a
  Rust content hash. Flutter Rust Bridge checks it at `RustLib.init`
  (`flutter_rust_bridge-2.3.0/lib/src/main_components/entrypoint.dart:103-112`); a mismatch throws before commands are served.
- The sidecar now catches that initialization failure before serving commands,
  logs a bounded cause such as `content_hash_mismatch`, emits an
  `engine_incompatible` error frame and exits 3. It does not print the raw
  exception, which can contain a path or engine internals.
- `bloom_engine.dart:29` still reports a hardcoded `engineVersion` constant in the
  `ready` frame; it is not read from the installed library.
- The doctor checks that the library path exists, but it does not verify the
  content hash or a supported version. The sidecar initialization is the actual
  preflight.
- Supported range: exactly the pinned binding tag. Other engine tags are
  unverified, even if they load; a different FRB content hash should fail closed,
  but that failure is not surfaced cleanly and no compatibility matrix exists.

### Rust and Dart dependencies

- `cargo metadata` reports 492 packages. The dominant license expressions are
  `MIT OR Apache-2.0` and `MIT`; the inventory also contains `MPL-2.0` (5),
  `Unicode-3.0` (18), `Zlib`, `BSD-3-Clause`, `CDLA-Permissive-2.0` and other
  expressions.
- The generated bundle covers 485 external Rust packages and 52 resolved Dart
  packages. A legal review of the MPL-2.0/Unicode-3.0 and compound expressions,
  and of the 48 packages without a package-specific file, remains open.
- The Dart packages themselves (`flutter_rust_bridge`, `freezed_annotation`,
  `lints`, `test` and their transitive set) are not vendored or staged. The
  operator runs `dart pub get`; the bundle records the resolved notices for
  distribution, not the package source.

### Cargo alone

Cargo installs or builds Bloom's Rust binaries only. It does not install:

- Dart 3.13.4;
- the sidecar source tree or its resolved pub packages;
- the OpenBubbles Flatpak, its engine library, or an existing registration;
- the exclusive engine-state ownership needed at runtime.

The documented runtime also requires the pinned engine state and library plus a
`dart pub get` in the staged sidecar tree.

## Blockers before any distribution

1. **Bloom license text.** Resolved: the root MIT `LICENSE` is staged, and the
   copyright holder is recorded as "Bloom contributors". Confirm that holder
   before distribution.
2. **Upstream license and notice.** Resolved: the Apache-2.0 `LICENSE` and the
   attribution `NOTICE` are staged under `lib/upstream`. The pinned upstream root
   has no `NOTICE`; the staged file is Bloom's attribution.
3. **Third-party notices.** Artifact resolved: the Rust/Dart bundle is generated
   and staged, with manifests and unique notice files. Open: legal review of the
   48 fallback notices, the MPL-2.0/Unicode-3.0 obligations and compound
   expressions. No current Dart manifest entry is marked `NO FILE`.
4. **Engine obligations.** Obtain a legal review of distributing Bloom binaries
   and sidecar sources that interact with an SSPL/closed engine. Do not bundle the
   engine. The process boundary is an engineering control, not a legal opinion.
5. **Engine preflight.** Resolved at sidecar initialization: an FRB content-hash
   mismatch is caught, logged as a bounded cause and returned as
   `engine_incompatible` before commands. The doctor remains path-only, and the
   ready-frame `engineVersion` remains a label rather than proof.
6. **Packaging gate.** Re-run the 4b staged-prefix and lifecycle checks after any
   packaging change. The phase 4 fault remains intermittent and the containment
   path was not exercised live.

## Decision

B-4c is a review, not a release. Distribution remains blocked by the legal review
of fallback and compound notices, the unresolved SSPL/closed-engine review, and
the exact-tag-only compatibility range. The Bloom MIT, upstream Apache-2.0/NOTICE
and third-party notice bundle artifacts are present and staged. The safe statement
is: Bloom source uses an MIT license; the vendored bindings are Apache-2.0 from the
pinned OpenBubbles tag; the third-party bundle records the resolved dependency
notices; the engine is external, user-supplied, and not covered by Bloom's license.

No distribution claim, no Cargo-only installation claim, and no supported-version
range beyond the pinned tag should be made.
